# Stage09 桌面舒适模式与真实导航补充设计

> **Status:** 用户于 2026-07-23 根据真实 Telegram Desktop 截图确认实施  
> **Scope:** 缩减 Telegram Desktop 的侵入式全屏行为，提供浏览器宽屏工作台入口，并让左侧导航只暴露真实可达的产品功能。

## 已确认的问题与根因

1. `AppContent` 在 Mini App 挂载时无条件调用 `requestTelegramMiniAppFullscreen()`。支持该能力的 Telegram Desktop 会立即进入宿主原生全屏，应用无法通过 CSS 留出 Windows 任务栏或系统窗口边界。
2. `AppShell` 只有“工作区”和“Base”拥有真实路由；消息、视图、自动化、机器人和设置中的多数图标是 `href="#..."` 占位入口，没有页面或状态处理器。
3. 左栏采用 72px 的纯图标样式，当前仅有无障碍名称，缺少用户可见的中文用途说明。

## 体验决策

```text
启动 Mini App
  -> ready + expand（保留）
  -> 不自动请求宿主全屏
  -> 始终提供“在浏览器打开完整工作台”
  -> 用户可主动选择“进入专注全屏”
  -> 全屏中可选择“退出全屏”或切换浏览器完整工作台
```

- Telegram 原生全屏是可选的专注模式，不再是默认打开方式。
- 浏览器完整工作台仍复用已部署的一次性 handoff 和 HttpOnly session，且在 Telegram 支持全屏时也可使用。
- 宿主全屏中的页面增加 12px 外层留白和圆角工作面，改善视觉压迫感；它不假装能恢复系统任务栏。需要工作切换时，用户应使用浏览器完整工作台或退出全屏。
- 左栏保留工作区、待确认、Bases、视图、自动化、团队 Bot、成员与权限和设置的产品扩展骨架。已实现的入口打开真实功能；未实现的“视图”“自动化”“设置”以禁用的“即将上线”入口呈现，不触发无处理的 hash 跳转。
- 每个左栏按钮具有中文 `aria-label`、原生 `title` 和悬停/焦点中文用途说明，例如“Bases：浏览和打开多维表格”。

## 验收标准

1. Mini App 首次打开不会调用 `requestFullscreen()`；仍调用 `ready()` 和 `expand()`。
2. 已处于全屏时可退出；非全屏时可由用户明确点击进入专注全屏。
3. 只要已经验证 Telegram 身份，浏览器工作台入口始终可见；现有 fragment-only handoff 安全边界不变。
4. 左栏每个可见图标都有明确状态：已实现入口打开真实功能；未来入口为不可点击的“即将上线”按钮。不存在 `#home`、`#bots`、`#management` 这类无处理占位跳转。
5. 图标悬停或键盘聚焦时显示中文名称和用途说明。
6. 聚焦测试、Mini App 构建和现有 handoff 安全测试通过；部署后由用户在 Telegram Desktop 验收窗口切换和左栏真实跳转。
